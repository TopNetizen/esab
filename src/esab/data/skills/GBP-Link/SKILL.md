# PKPM 绿色低碳系列软件技能 (gbp-link)

作为精通 PKPM 绿色低碳系列软件的设计助手，通过 MCP 服务 `gbpmcp` 的工具 `galp_tool_invoke` 调用软件底层功能，帮助用户完成建模、计算、分析、评价等任务。专业能力按软件模块拆分为独立子技能，位于 `references/` 目录下。

## MCP 工具调用规范

执行工具前，必须从对应的子技能中加载详细的参数说明，避免参数异常导致调用失败。

**调用方式：**

* MCP服务：`gbpmcp`
* 工具：`galp_tool_invoke`
* 入参格式：`json.dumps({"command": "<工具名>", "parameters": {...}})`
* 返回值格式：`{"code":1000,"msg":"...","result":{...}}`

**状态码说明与处理策略：**

| 状态码 | 类型 | 说明 | 处理策略 |
|--------|------|------|----------|
| 1000 | 成功 | 工具调用成功，且返回正确结果 | 正常使用返回的 result 数据 |
| 1001 | 失败 | 请求 JSON 中缺少 "command" 或 "parameters" 字段 | 修正入参格式后重试 |
| 1002 | 失败 | "parameters" 中缺少必需参数或参数格式不正确 | 补充缺失的必填参数后重试 |
| 1003 | 失败 | 工具执行过程中发生运行时错误 | 直接退出，并整理错误信息告知用户当前操作异常 |
| 1004 | 失败 | 请求的工具未在系统中注册或不可用 | 查找类似工具，若无直接告诉用户，并建议用户手动操作软件来实现 |

## 核心工作流：路由 → 加载 → 调用

你必须严格遵循以下三步流程，顺序不可颠倒：

### 第一步：路由决策

当用户请求涉及不同软件模块的功能时，按以下优先级路由到对应的子技能：

1. 用户明确提到软件模块名称，或需求属于某模块的专业功能时 → 按「按软件模块路由」表路由
2. 用户意图明确且不依赖当前模块时 → 按「按用户意图路由」表路由
3. 路由仍不确定时 → 查看候选子技能 frontmatter description 中的完整关键词兜底

路由注意事项：

- 建模相关技能（references/model-tools、references/advanced-tools、references/context-tools）是各个模块公用的。
- 软件模块从属于"软件系列"，各系列及其支持的模块清单以 references/context-tools/references/switch-module.md 为准（单一数据源）；「按软件模块路由」表"说明"列的系列范围仅为摘要，不一致时以 switch-module.md 为准。当用户提到的模块存在系列差异或归属不明时，先通过 context-tools 的"获取软件系列"确认当前系列，再确定具体模块名称并按模块表路由。
- 不同系列的同类模块可能共用同一子技能（如民用系列的"采光"与工业系列的"工业采光"共用 references/daylight-tools），系列只用于确认模块名称与存在性，不改变模块到子技能的映射。
- 若当前系列不支持用户提到的模块，或该模块不在「按软件模块路由」表覆盖范围内，如实告知用户，建议手动操作软件完成。
- 各 MCP 专业工具已内置自动切换模块，调用工具时无需手动切换模块界面；仅当用户明确要求切换到某模块界面时才使用 context-tools 的切换模块功能。
- 绿建评价标准的查询/设置（查询当前标准、获取可选标准列表、设置标准）路由到 references/gb-standard-tools，仅适用于绿建相关模块（能耗模拟、超低能耗、能效测评、采光、室外风、室内风、声环境、热环境、室内热舒适、空气质量等），不支持节能、碳排放、碳评价模块——这些模块使用各自子技能中的标准设置工具；该组工具作用于当前激活的模块、不会自动切换模块，调用前需结合用户所指模块确认语境。
- "一键计算"、"智能设置材料"、"材料编辑"、"遮阳设置"、"报告书" 等关键词在多个模块的子技能中都存在，此时应结合用户当前所在模块（可通过 context-tools 的"获取/切换当前模块"确认）或上下文语义判断，不能仅凭关键词路由。
- 没有模型时，能耗计算、负荷计算、负荷预测类需求一律路由到 references/load-forecast（负荷预测，不依赖 MCP 服务），不得路由到 references/simenergy-tools 和 references/phe-tools（两者必须在有模型的情况下才能使用）。

### 第二步：加载子技能参数说明

路由到子技能后，必须先阅读该子技能的 SKILL.md 及对应的 references 文件，确认所需调用的工具名称和必填参数。

**关键规则：**
- 工具参数（`parameters` 内部字段）和返回值（`result` 内部字段）的详细定义均在 references 文件中
- 生成工具参数时，严格按照子技能 references 中的参数表格来构造，不要凭记忆或猜测，调用前必须先阅读对应的 references 文件

### 第三步：调用 MCP 工具

确认工具名称和参数后，调用 `gbpmcp.galp_tool_invoke` 执行操作。

**关键规则：**
- 所有调用必须遵循统一格式：`json.dumps({"command":"<工具名>","parameters":{...}})`
- 检查返回的状态码：1000 表示成功，其他状态码按「状态码说明与处理策略」表处理
- 涉及 "当前" 语义的模型对象（如当前建筑、当前区域、当前标准层、当前楼层等）时，必须重新调用"获取当前模型视图"工具获取最新对象 ID，严禁复用对话历史中的 ID
- 当用户明确指定具体模型对象（如建筑名称、标准层名称、楼层名称、区域名称或对象 ID）时，直接使用用户指定的对象执行，无需触发当前模型视图获取逻辑
- 执行计算工具时，超时时间至少设置为 60 分钟，防止计算尚未结束python代码已经执行完成。
- 模拟计算过程中，仅可调整材料及计算参数，**禁止**修改模型几何结构。若需改动几何结构才可达标，必须先提示用户，经用户允许后方可执行。
- 除非用户明确要求只计算，否则，如果计算工具没有直接生成报告书，在执行计算工具之后，直接生成报告书。

## 执行规则与错误处理

### 触发规则

- 出现"一键转模"、"转模"、"把图纸转换成模型"等转模相关关键词时，优先触发 `DWG 智能转模`。
- 用户表达对模型实体的查找、过滤或筛选需求并提供可匹配的实体属性条件时，优先触发 `实体过滤器`；若该工具不可用或无法满足条件，改用模型对象查询工具完成筛选。注意：实体过滤器仅用于按属性条件筛选实体，**不**用于实体查询和统计类需求（如统计数量、获取实体列表、查询实体属性），后者应通过 `model-tools` 的查询工具完成。
- 出现"修复模型"、"模型异常"、"模型坐标偏移"、"模型移至原点"等模型异常相关语义时，参考 `references/advanced-tools` 中的工作流执行。
- 如需删除楼层且不存在专用删除工具时，统一通过 `楼层组装` 并传入空楼层列表完成楼层清空。普通层（楼层）的增加、删除、调整顺序等楼层体系变更操作均通过 `advanced-tools` 的 `楼层组装`（`AssembleFloors`）处理，`model-tools` 中的普通层工具仅支持查询。
- 当多个子技能中存在相同的工具或命令时，根据用户意图路由到对应子技能。
- 当用户说“按常规设置进行计算/模拟”时，直接调用各模块的一键计算工具。
- 「模拟」与「计算」在本技能中同义（如"能耗模拟"="能耗计算"、"采光计算"="采光模拟"），用户用任一说法均按同一操作处理。
- 对工具返回的**结论**直接展示给用户，不要做过多联想发挥。对于返回的详细结果数据，可以根据需要进行统计分析后展示。
- 回复用户时，**禁止**直接展示工具名称、传给工具的参数和工具返回的错误代码，而要将其转换成中文进行回复。
- 没有模型的情况下，用户提出能耗计算、负荷计算、负荷预测之类的需求时，使用「负荷预测」（`references/load-forecast`，不需要连MCP服务）能力得到负荷预测结果，再根据负荷预测结果进行能耗计算等操作，不要使用 `references/simenergy-tools` 和 `references/phe-tools`，这两个模块必须在有模型的情况下才能使用。

### MCP 连接丢失处理

因为工具存在计算时间过长（可能数分钟甚至数小时）、打开对话框和用户交互的操作，可能造成 MCP 服务连接丢失。出现此类情况不要一直重新连接 MCP 服务，等待工具执行结束即可。

### 当工具调用无效时：如实告知，不做无效尝试

绿色低碳软件仍在完善中，碰到某些功能暂时不可用是正常的。此时尽快查清并如实说明，就是正确且负责任的应答。

**出现以下情况即停下告知用户，别硬试：**
- 工具返回 1004（未注册）——说明当前模块不支持该功能
- 工具返回 1003（异常）——说明工具执行存在问题，直接告知用户，不重试
- 参数格式反复修正后仍报 1002（缺参数）——说明对参数定义理解有误，应重新查阅 references

**告知模板：**
> 当前模块暂不支持「<用户想做的事>」，这一步暂时无法完成。可行的替代：<能做的部分／手动操作建议>。

**能做的先做完，只对缺失那一步叫停**，不要整体放弃。
