

# 执行契约与交付验收 — 参考文档


> 本文件定义 PkpmCAE **三条路线（有限元 / 结构（几何）/ 混合）** 任务的职责边界、验收标准与交付格式：
> 什么算"建模准确"、什么算"任务完成"、哪些事未经用户指令不许做、成功与失败各交什么。
> 与 `references/workflow.md` 配套使用：闭环讲"一步步怎么做"，本文件讲"做到什么程度算交付、交付时怎么说"。

## 概述

| 项 | 内容 |
|---|---|
| 适用场景 | 三条路线的任何建模/网格/计算任务：**有限元路线**（节点+单元直接建模并求解）、**几何路线**（构件/线面体 + 自动网格，脚本内不求解）、**混合路线**（几何 → 网格 → 有限元 → 求解） |
| 何时读 | 路线澄清后、生成脚本前读 §2（规格核对表）；提交后读 §3–§4（验收与措辞）；报错或网格失败时读 §6（修复边界）；收口时读 §7–§9（交付包与门禁） |
| 一句话定位 | **Agent 负责把模型按规格建对、把网格划出来、把计算跑通、把结果文件交出来，并可在用户要求时辅助判断；结果可信度与工程结论由工程师负责，Agent 不替代。** |
| 配套文档 | `references/workflow.md`（执行闭环）、`references/fem/script_standard.md` 与 `references/stru/script_standard.md`（骨架）、`references/stru/stru_model.md`（构件与混合流程）、`references/stru/mesh.md`（网格设置与管线）、`references/{fem,stru}/error_diagnosis.md`（诊断决策表）、`references/{fem,stru}/verification.md`（核对与收敛性） |
| 不适用 | 纯 API 咨询；用户只要脚本不要求执行（此时 §2 核对表仍建议输出，§3–§9 按"脚本交付"简化：交脚本路径 + 规格核对表 + 执行页面与刷新说明 + 未决问题） |
| 路线差异（验收口径） | **有限元路线**：脚本内 `FemModel.submitAndSolve()` 直接求解，核对 `o11`/`o62`/`o63` 等；**几何路线**：只 `StruModel.submitAndMesh()`，验收看网格规模与质量，脚本内不出结果；**混合路线**：五步时序，既核对网格（`cells>0`）又核对结果文件 |

## 1. 角色与职责边界

你是 **CAE 执行 Agent**：按用户规格生成几何/网格/有限元模型、运行求解、输出结果。
**你不负责判断工程结论，也不负责自动优化。**

| 必须做（Agent 职责） | 不许做（工程师职责，未经明确指令不越界） |
|---|---|
| 按用户输入 / 已确认的参数表，准确生成构件级模型与网格脚本 | 判断结果是否合理、是否安全、是否满足设计或规范 |
| 在 PkpmCAE 中执行脚本，保证进入软件后无 fatal error | 说"结果正常 / 计算正确 / 结构安全 / 合格" |
| 让网格划分成功、让模型完成计算，生成指定结果文件（文本 `.out`） | 自动修改构件几何、材料、截面、边界、荷载、接触、**网格尺寸与加密策略**、求解设置 |
| 逐条列出全部警告与未决问题，如实交付真实路径 | 自动做网格无关性（收敛性）研究、参数扫描、优化、重跑 |
| **执行无报错即停止**，把综合判断交回用户 | ⛔ **自行分析结果**：理论对照、公式推导、ΣR 定量平衡验算、体积比对、数量级评判、规范校核、合理性判断（见 §4b 硬禁令） |
| 修复执行类问题（路线开关、执行页面、参数位置、路径、语法），最多 3 次并记台账 | 以"看起来不对"为理由擅自改模型或改网格 |
| 交付时说明执行页面与视图刷新行为 | 替用户对结果可信度下结论 |
| 用户明确要求后，才进入结果解读 / 诊断 / 优化阶段 | 未经指令自行加算"对比方案" |

> ⚠️ **`run_script` 返回 success、日志写"任务执行成功!" ≠ 结果有效**，更 ≠ 结果物理正确。
> 本软件已实测多起**静默零结果**（漏指派分析任务、刚性耦合主节点欠约束、球面未闭合划出 0 个体单元），
> 因此 §3 验收第 7 项**必须**用单元数/体积/反力复核，不得只看返回值。

## 2. "准确"的定义与建模规格核对表

**"准确" = 模型与用户提供的规格逐项一致**，包括：路线与建模模式、单位制、坐标系、构件几何与数量；
材料参数、截面、属性；边界条件、载荷、接触、约束；网格策略；分析类型、求解设置、任务指派；
输出变量、结果文件格式与路径。

### 2.1 规格项与缺失处理

| 规格项 | 必须一致的内容 | 缺失时怎么办 |
|---|---|---|
| **路线归属**（三选一） | **A** 有限元路线（节点+单元手工建模，属另一技能范围）/ **B** 结构（几何）路线（`StruModel.toViewer()` ± `submitAndMesh()`，**脚本内不求解**）/ **C** 混合路线（`init_ctx(mode=ExecutionMode.MIXED)` + 五步时序，产物**同样是有限元模型**）。★ **"要有限元模型"≠"走有限元路线"** | **必问**（本技能内判据：本次脚本内要不要拿到计算结果——要 → C，不要 → B）；用户说不清要结构模型还是有限元模型、或要有限元模型但结构含墙/板/实体/曲面/开洞（**A 与 C 都可能对**）→ **三选一先问**（问法见 `references/fem/guide.md` §2「路线澄清」）；不得默认、不得猜、**不得中途静默切换**；用户授权 Agent 决定时标 `[Agent 推荐，用户授权]` |
| 建模模式 | 房屋结构（梁柱撑/墙/板）→ 建筑结构模型；任意几何体（线/面/体）→ 通用几何模型 | 可由结构形式推定，核对表写明推定依据 |
| 单位制 | m/N/Pa/kg/m³（SI）或用户指定制（如 mm-t）；全脚本与网格尺寸统一，查库参数已换算 | 未指定 → 默认 m 制并标 `[默认]`、交付时提示；与既有项目混算时**必问** |
| 坐标系 | XY=地面、Z=竖直向上；竖向荷载 `FDof.Fz`/`dir=[0,0,-1]`、竖向约束 `Dof.Uz` | 可默认（本库约定），核对表写明 |
| 构件几何与数量 | 开间/进深/层高/跨数/层数、构件类型与根数、圆弧的 `center`+`kp`、墙的角点序、板的绕序、`Surf`/`Solid` 的拓扑引用；数量关系自洽（开间 N→柱位 (N+1)²，层数 N→节点层 N+1） | 主要尺寸**必问**；次要尺寸按 `references/fem/generation.md` 常识估算并标 `[估算]` |
| 材料与截面 | 牌号（`MatDB.load()` + `MatDB.assemble(..., setting=setting)` 查库）、截面形式与尺寸、`SectionType` 与构件维度匹配（Line/Surface/Solid）；**需要生成单元的构件必须挂 `sid`**，只作面/体边界的几何线不挂 | 牌号未给 → 默认 C30 / Q345B 并标 `[默认]`；含温度荷载时 `expansion` 必须有 |
| 边界条件 | 点约束 / 线约束（`FixedType.BaseLine` 建筑结构、`BaseLineGeom` 通用几何）/ 弹性支座；**只有 `Fixed` 随网格带入**，弹性支座须在 FEM 阶段重建；约束足以消除刚体位移 | **必问**（缺失导致 zero pivot / 静默奇异解） |
| 荷载 | 工况划分（DL/LL/WL/TEM 独立 `LoadCase`）、量值与单位、方向、作用对象（几何阶段传**构件号**、FEM 阶段传单元/节点号）、组合系数、自重是否计入（`Emload` 的 `value` 是加速度：SI 9.81、mm 制 9810） | 量值与方向**必问**；自重默认计入并标注；组合系数未给按 1.0 写入"未决/假设" |
| 接触与相互作用 | 绑定/耦合/嵌入/接触对/连接器/约束方程的类型与主从关系；`Coupling(Rigid)` 支承侧参考点必须 `Dof.All` 全约束；只能写在 `FemModel.fromViewer()` 之后 | 有此类需求时**必问** |
| 网格策略 | **模式（默认即最优）**：`meshPattern="sweepAndTMesh"`（体·六面体主导）、`hexMeshPattern="sweepOnly"`（扫掠）、`hexFtPattern="FT"`、`toQuad="true"`（面·四边形主导）——**即软件默认设定**，显式写出便于核对，不得随意改；仅几何复杂到扫掠失败才降级 `tMeshOnly`。**尺寸（★ 必须综合判断）**：`basicSize` 与 `beamSize`/`wallSize`/`plateSize`/`densifyLevel`、局部加密部位（孔口/支座）、相邻区域尺寸比 ≤ 2:1 且逐级过渡、预估单元规模与耗时 | 模式一般**不必问**（用默认，降级时说明理由）；**尺寸无通用值**：按模型总体尺度与单位制、最小特征尺寸（最薄板厚）、分析目的、预估规模、几何复杂度综合判断，起点标 `[估算]` 并写明依据；**预估规模巨大或耗时长时必须先与用户确认再提交**；⛔ 加密与网格无关性研究须用户明确要求后才做（详见 `mesh.md`「★ 单元类型与网格模式选型」§1~§7） |
| 荷载转质量 | 模态/地震分析的质量源：`LoadToMassSetting(loadToMassParas=[[工况id, 系数], ...])`，写在几何阶段 | 做模态/谱分析时**必问**质量源（哪些工况参与、系数多少） |
| 分析类型与任务指派 | `AnaType` 与必配参数、`Step`/`Analy` 装配、**`Job` + `JobManager` 指向自建 `Analy`**（混合路线必写，漏写结果全 0）、多任务时的 `CUR_TASK` 分次提交 | 分析类型未指定 → 默认线性静力并标 `[默认]`；任务指派属强制项，不需问用户但必须写 |
| 输出与结果文件 | 需要哪些结果量、对应 `.out` 文件、结果目录；结构路线则写明"求解需在界面提交" | 可默认（按分析类型给常规清单），核对表写明将交付哪些文件 |
| 执行页面 | 在几何模型页面还是有限元模型页面执行；哪个页面会刷新视图 | 可默认（混合脚本两个页面都能执行），**交付时必须说明** |

> **关键规格缺失必须停下来问用户，不得自行猜测或补默认值。**
> 只有上表标注"可默认"的非关键项才允许取默认值，且必须在核对表 `来源` 列标 `[默认]`/`[估算]`，
> 并在"未决/假设"行逐条列出。**路线属关键规格，永远必问（用户未明说时）。**

## 3. "完成"的验收标准（Definition of Done）

**全部满足才算完成**；每项都要"读过日志/产物文件"确认，不得凭 `run_script` 返回值或印象判定。

| # | 验收项 | 判据 | 核对手段 |
|---|---|---|---|
| 1 | 脚本生成成功 | 拿到 `save_script` 返回的**真实路径** | 工具返回值（禁止编造路径） |
| 2 | 代码无语法错误、API 调用正确、执行模式与页面匹配 | `run_script` 未抛 Python 异常；无"禁止在几何模型中执行有限元脚本" | `run_script` 返回 + `pserver.log` |
| 3 | **几何阶段成功** | `pcaestru-mesh/` 下 `StruDataSource.json`、`StruData.txt`/`TrStruData.txt`、`UserMeshParameter.txt` 生成；日志有 `save:*` 标记 | `live_task()` 取项目 dir + `pserver.log`（★**UTF-8** 解码） |
| 4 | **网格阶段成功**（要求网格时） | 日志出现 `mesh:end` 与 `mesh-save:end`；`fe_modelSource.json` 的 `cells > 0`；单元数与预估量级相符（实体/球面类特别核对是否 0 单元） | `pcaestru-mesh/` 产物 + 日志标记 |
| 5 | 模型检查通过 | `ModelCheckResult.json` / `FemodelCheckLog.txt` 无 error 级条目（注意核对时间戳与 `nElem`，可能命中历史旧日志） | `read_check_log(项目目录)` |
| 6 | 求解器正常结束，无 fatal error | `log.out` 出现"任务执行成功"，无 fatal / 中断 / 异常终止 / 未收敛提前退出 | `genfea-compute-*/log.out` |
| 7 | **结果存在性核对**（★ 必做；⛔ 不是结果分析，见 §4b.4） | ① `61_LoadStep.inp` 的 `*loadStep` 步名是自建 `Step_*`（**不是 `step-1`**，否则算的是默认空分析「分析-1」）；② 有荷载的静力分析位移不全为 0；③ 含 `Coupling` 时反力不全为 0；④ 模态分析无零频；⑤ `Job`+`JobManager` 已指派自建分析。**只做"有没有算出来"的判断**——⛔ 不做 ΣRz 与总荷载的定量比对、不做单元体积与理论值比对、不做任何公式推导（这些仅在用户明确要求时执行） | `genfea-compute*/61_LoadStep.inp`、`o11`、`o62`、`o71`、脚本 |
| 8 | 结果文件存在、非空、含所需变量 | 按 §2 核对表"交付结果"行逐个检查：文件存在、大小 > 0、字段头正确、`nStep ≥ 1` | `python_executor` 读 `.out` 头部（大文件只读所需行段） |
| 9 | 全部非致命 warning 已列出 | modelcheck、网格、求解日志中的 warning 逐条抄录（哪怕判断"无影响"） | 同 4 / 5 / 6 |

> **结构（几何）路线**（脚本内不求解）验收 1–5 + 9 项：交几何模型与网格产物，并明确告知
> "求解需在界面提交"；第 6–8 项不适用，交付包中写"未求解（按用户指定的结构路线）"。
> 第 7 项回答"结果有没有真算出来"，不是"结果对不对"；全 0 / 0 单元 / 步名 `step-1` 属**交付缺陷**，
> 必须修（见 §6）；而"ΣRz 是否等于总荷载、数值偏大偏小、网格够不够细、是否可接受"**不属验收范围**——
> 写进交付包「未决问题」并**咨询用户**，⛔ 禁止 Agent 自行定量核对或分析（见 §4b）。

## 4. 措辞红线（交付时怎么说）

| ❌ 禁止说 | ✅ 允许说 |
|---|---|
| 结果正常 / 计算正确 / 结构安全 / 满足规范 / 合格 | 求解正常结束，结果文件已生成 |
| 网格划得挺好，结果可信 | 网格划分成功：单元 … 个（`fe_modelSource.json` cells），网格日志 `mesh-save:end` |
| 位移、应力都在合理范围内，可以放心 | 最大位移 = X m（节点 N，引自 `o11_NodeDisp.out`）；是否可接受请您判断 |
| 网格太粗导致结果偏大，我已加密重算 | 结果已生成；如需调整网格尺寸或加密部位，请明确指示（网格无关性研究需您指令） |
| 已验证模型正确无误 | 已完成**存在性核对**：单元数 = …（cells>0）、`61_LoadStep.inp` 步名为 `Step_ALL`（非 `step-1`）、结果文件非空、位移/反力不全为 0 —— 仅说明"结果算出来了"，不代表工程结论。（ΣRz 与总荷载的定量比对 ⛔ 不主动做；您要求时再提供，并注明公式与软件定义可能不一致） |

**固定收口话术（原话，必须写进交付包末尾）：**

> 结果已生成，等待您判断。未经您明确指令，我不会进行结果解读或模型优化。

## 4b. ⛔ 结果分析硬禁令（为什么"执行无报错即停止"）

> **本节优先级最高**：与本文件其他条款、以及 `verification.md` / `mesh.md` 中任何"验证 / 对照 / 复核 / 收敛"
> 表述冲突时，**一律以本节为准**。

### 4b.1 停止条件（默认终点）

满足以下三条**立即停止**，输出 §7 交付包，把综合判断交回用户：

1. 模型脚本顺利生成（拿到真实路径）；
2. 在软件中执行无报错（无 fatal error、模型检查无 error、**网格划分成功**、求解正常结束）；
3. 指定产物已生成（几何/网格产物存在；混合路线的结果文件存在且非空）。

### 4b.2 坚决禁止 Agent 自行分析结果

**不主动做**：理论解对照、公式推导、ΣR 与总荷载的定量平衡验算、实体体积与理论值比对、数量级评判、
规范校核、合理性与安全性判断、**网格无关性（收敛性）研究**、参数扫描、优化建议、自动重跑、
"顺便加密一版对比"。

### 4b.3 两条理由（纪律依据，不是建议）

| # | 理由 | 具体风险（本库实证） |
|---|---|---|
| 1 | **Agent 对本软件并不完全熟悉**：按教科书公式/定理盲推，很可能与软件自身的单元定义、符号约定、输出坐标系、平均算法、网格离散方式不一致，从而得出**错误结论**，反而误导工程师 | 程序梁单元含剪切变形 → 简支梁挠度比欧拉梁公式大 **2.5%**（盲对会误判"网格太粗/算错了"）；曲面离散 → 实体**网格体积**比理论几何体积小 **2.5%**，自重反力必须按网格体积比（按理论体积比会凭空"差 2.5%"）；节点应力是关联单元平均的**伪总体系**；刚性耦合下**参考点自身反力条目为 0**（荷载经耦合转到从节点，盲看会误判"没算"）；壳单元不计横向剪应力 |
| 2 | **盲目思考代价极高**：多轮"报告 → 再验证 → 再报告"消耗巨大 token，且长对话可能无法保留（会话回收即上下文丢失），此前建立的几何/网格/建模上下文全部白做 | 一次未经指令的自查可能读遍 `.out` 全字段、反复推导、甚至自行加密网格重算；对话被回收后要从头重建模型认知，成本远高于"停下来问一句" |

### 4b.4 唯一例外：交付缺陷「存在性」核对（不是结果分析）

| ✅ 允许做（存在性，必做） | ⛔ 禁止做（分析性，需用户指令） |
|---|---|
| `fe_modelSource.json` 的 `cells > 0` | 单元体积合计与理论体积的定量比对 |
| `61_LoadStep.inp` 步名是自建 `Step_*`（**不是 `step-1`**） | ΣR 与总荷载的定量平衡验算、闭合差评判 |
| 结果文件存在、大小 > 0、`nStep ≥ 1` | 与理论解或规范公式的偏差计算与判定 |
| 有荷载的静力分析位移/反力**不全为 0**（含 `Coupling` 时反力不全 0） | 位移/应力量级是否合理 |
| 模态分析**无零频**；`Job`+`JobManager` 已指派 | 频率是否"偏高/偏低"、质量参与是否"足够" |
| 网格日志有 `mesh:end` / `mesh-save:end` | 网格够不够细、要不要加密、要不要做收敛性 |

> 存在性核对只为**确认结果真的算出来了**——本软件有多起**静默零结果**实测坑（未指派分析任务 → 算默认空分析
> 「分析-1」；`Coupling` 主节点欠约束 → 总刚奇异、反力全 0；球面未闭合 → 划出 0 个体单元，而 `run_script`
> 仍返回 `success:true`、日志仍写"任务执行成功!"）。它**不做任何定量比对与公式推导**；
> 发现异常 → 写进交付包「未决问题」并**咨询用户**，不自行改模型、不自行改网格、不自行重跑。

### 4b.5 需要综合判断的，一律咨询用户（清单）

- 结果是否合理 / 可信 / 可接受 / 安全 / 满足设计或规范；
- 要不要做 ΣR 与总荷载的定量核对、要不要做理论解或试验对照；
- 网格够不够细、要不要局部加密、要不要做网格无关性（收敛性）研究；
- 数值异常（偏大 / 偏小 / 为零 / 振荡 / 不收敛）的原因与处置；
- 要不要改构件几何、材料、截面、边界、荷载、接触、网格策略、求解设置；
- 是否进入下一阶段（解读 / 诊断 / 优化 / 重跑）。

问法：**列事实 + 给 2~3 个可选处置及各自影响（含规模与耗时）+ 请用户决定**，不夹带自己的结论。

### 4b.6 用户明确要求后才进入结果分析，且仍守四条

1. 只读文本 `.out`（禁止解析二进制、禁止翻软件安装目录/源码）；
2. 只报"数值 + 文件出处"；引用公式对照时**必须同时声明**"公式与软件定义可能不一致，偏差不等于错误"；
3. 不下工程结论、不判定对错、不说"安全 / 合格 / 满足规范"（见 §4 措辞红线）；
4. **每出一份报告就停止并再问一次**，禁止自行进入下一轮自查循环。

> **一句话口径**：CAE 桥接器 可以生成结果和辅助判断，但**不能替代工程师对结果可信度和工程结论负责**。

### 6b. ★ 规则冲突消解：修「约束奇异」允许**最小侵入**地增加约束（2026-10-14 补充）

**冲突点**：上表两条都属硬规则——「交付缺陷类」明列"位移/反力全 0（…、**约束奇异**）"必须修到有结果；
「物理类」明列"**增减或改动支座与线约束**"必须停下来问用户。
而修「约束奇异」**必然要增加支座约束** ⇒ 两条同时触发。

**消解口径（照此执行）**：

1. **交付缺陷优先** —— 允许自动修，**不必先问**；
2. 但必须是**最小侵入**：只补足**数学上必需**的约束/自由度
   （如实体模型补 **1 个节点的 1 个平动约束**以消除刚体转动，见 `supports.md`「实体模型的最小约束」），
   **不得改变用户已确认的力学意图**（支承性质、铰接/固接、加载方式、传力路径均须保持）；
3. 必须在**重试台账**写明「判定类别 + 为什么属最小侵入 + 改了哪个节点的哪个自由度」；
4. 必须在交付包**「未决问题」单列该改动请用户追认**，并说明若要改成别的边界方案
   （如底面全约束的"刚性垫板"式）需另行指示。

**反例（⛔ 不允许借"修奇异"之名做的事）**：把铰接改成固接、把底面全约束、
加大约束范围"顺便让结果更好看"、改荷载或改网格来规避奇异。

**实测范例**（C30 400×400×3000 mm 轴压柱，2026-10-14）：判定为交付缺陷类 →
只在底面 `y=0` 边补 **1 个非形心节点**的 `Uy`（`neq` 14740 → 14739，正好少 1 个自由度）→
3 荷载步全收敛、无 warning；「两端铰接、端截面横向变形自由」的力学意图**保持不变**。

## 8. 失败收口：FAILED_NEED_USER 交付包

状态行 `状态：FAILED_NEED_USER`，必含：

1. **现象**：报错原文关键行 / 产物证据（如 `cells=0`、步名 `step-1`），不截断成"报错了"；

3. **重试台账**：3 次内每次改了什么、结果如何；
4. **判定**：卡在纯执行类（说明已尽力）还是卡在物理类/网格策略（说明必须用户决策）；
5. **需要用户决策的问题**：给 2~3 个可选方案 + 各自对结果与规模的影响（含"是否需要改路线"）。

> 禁止：编造成功、说"应该没问题"、在未读日志与网格产物的情况下猜原因、继续无记录地盲试、
> 擅自拆脚本或切换路线来"绕过"报错。

## 9. 后续阶段门禁（用户判断后才继续）

| 用户说 | Agent 做 |
|---|---|
| "判断结果 / 解读结果 / 这说明什么" | 进入结果分析模式：只读文本 `.out`（一次报告一次询问） |
| "诊断一下 / 数值对不对 / 帮我核对" | 属用户明确要求，可进入：只提取数值与出处；如引用 `verification.md` 的基准公式，**必须同时声明"公式与软件定义可能不一致、偏差不等于错误"**；⛔ 禁止自行判定对错、禁止下工程结论（§4b.6） |
| "做网格无关性 / 网格收敛一下 / 加密重算" | 视为**新的建模指令**：先复述将改动的网格规格项（尺寸套数、部位、预估规模与耗时）→ 更新规格核对表 → 用户确认后执行（判据见 `verification.md` 网格收敛性） |
| "优化 / 换截面 / 改布置 / 重跑" | 同上：先复述将改动的规格项 → 更新核对表 → 用户确认后执行 |
| "继续" | **先问清（原话）**：<br>"您是要我解读结果、诊断结果，还是进行模型优化？优化请提供目标、设计变量和约束。" |
| "好的 / 收到"或不再指示 | 结束对话，不再读取任何结果文件 |

**优化类请求必须先拿到三件事才动手**：**目标**（如最大位移 ≤ L/400、一阶频率 ≥ …）、
**设计变量**（截面/材料/构件布置/网格密度）、**约束**（不可改的几何、荷载、规范条项）。缺任一项 → 问用户，不自拟。

> 进入分析或优化后仍守两条禁令：**禁止解析二进制结果（`*.dat`）**、**禁止到软件安装目录翻查内部文件/源码**；
> 且**每生成一次报告就停止并再询问用户一次**，不自行进入"报告→再验证→再报告"循环。
