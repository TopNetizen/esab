

# 任务执行流程（Playbook）— 三条路线的端到端建模与计算闭环

> 本文件是**执行闭环**（一步步怎么做）；验收标准与交付格式见 `references/execution_contract.md`。
> 三条路线共用同一闭环，路线专属步骤标注为「A 结构（几何）路线」「B 混合路线」；**有限元路线**按同一闭环执行，
> 第 3 步收口改为 `FemModel.toViewer()` + `FemModel.submitAndSolve()`（脚本内直接求解），产物核对见 `references/fem/verification.md`。


> 本文件告诉 AI Agent 如何用本技能**跑完整任务**（不只是写脚本）。
> 只要用户要求"建几何模型 / 划分网格 / 建完再算"，就必须走完本闭环。
> 不可协商规则见 `references/stru/guide.md`（有限元路线见 `references/fem/guide.md`）；API 细节见 `references/`。

## 1. 执行闭环（强制）

```text
┌────────────────────────────────────────────────────────────────┐
│ 0. 环境确认 ENV   按 references/platform_tools.md §0 三级判别：      │
│                   cae-mcp → 内置工具 → 皆无则告知用户需连接    │
│ 1. 澄清 CLARIFY   先定路线（结构 / 混合，未明必问），再 ≤4 问  │
│ 2. 生成 GENERATE  一律 save_script 手写 Python（骨架见标准）   │
│ 2.5 规格核对 SPEC 运行前输出"建模规格核对表"，对齐用户规格     │
│                   （execution_contract.md §2：路线/构件与数量/ │
│                   网格参数/任务指派/执行页面）；关键规格缺失   │
│                   → 停下来问，不猜不擅补；默认项标 [默认]      │
│ 3. 提交 RUN       按路线收口（见第 3 步）                      │
│ 4. 诊断 DIAGNOSE  pserver.log → pcaestru-mesh/ → 检查/求解日志 │
│ 5. 迭代 ITERATE   执行类问题可自修（≤3 次，记重试台账）；      │
│                   要改物理设定/网格策略 → 停下来问用户         │
│ 6. 收口 CLOSE     ⛔ 执行无报错即停止：只做「存在性」核对      │
│                   （cells>0、步名非 step-1、结果文件非空、     │
│                   位移/反力不全 0、模态无零频、Job 已指派）    │
│                   → 输出 SUCCESS_WAIT_USER 交付包 + 页面/刷新  │
│                   说明 → 立即停止并询问是否要用户自行深算      │
│                   禁止自行 ΣR 定量平衡/理论对照/公式推导/      │
│                   量级评判/网格收敛性/优化建议/重跑            │
│ 7. 分析 ANALYZE   默认不进入。仅用户明确说"判断/解读/诊断/     │
│                   优化/网格收敛/重跑"后才进入（只说"继续"→     │
│                   先问清意图）；进入后只读文本 .out、只报      │
│                   数值 + 出处、明示公式可能与软件定义不一致、  │
│                   不下工程结论；禁止解析二进制/翻软件源码；    │
│                   每出一份报告即停止再问一次                   │
└────────────────────────────────────────────────────────────────┘
```

### 第 1 步 — 澄清（不可跳过）

**先定路线，再问参数**；至多 4 个问题，每个都给默认值：

| 必确认项 | 默认值建议 |
|---|---|
| **模型路线**（未明**必问**，**三选一**） | 判据：纯杆系且要结果 → **有限元路线**；只要几何模型/网格、脚本内不求解 → **结构（几何）路线**；含墙/板/实体/曲面等需自动网格且要结果 → **混合路线**。★ 用户说不清要结构模型还是有限元模型，或要"有限元模型"但结构含墙/板/实体/曲面（**有限元路线与混合路线都可能对**）→ **三选一先问**（第 1 项即转交有限元路线），问法见 `references/routes.md`「路线归属澄清」；不得猜测开工、不得中途静默切换 |
| 建模模式 | 房屋结构（梁柱撑/墙/板）→ 建筑结构模型；任意几何体（线/面/体）→ 通用几何模型 |
| 结构形式与关键尺寸 | 按用户描述；缺失时按 `prompts/ai_guide.md` §工程常识估算表 |
| 材料 | 混凝土 C30 / 钢材 Q345B（一律 `MatDB.assemble` 查库） |
| 单位制 | 用户未指定 → 默认 m 制（SI）并在交付说明中提示；指定时查库参数换算一致 |
| **网格模式**（默认即最优，一般不问） | ★ **体网格六面体主导 + 面网格四边形主导 + 六面体扫掠**＝软件默认：`meshPattern="sweepAndTMesh"`、`hexMeshPattern="sweepOnly"`、`toQuad="true"`；只有几何复杂到扫掠划不出（碎面/回转体/球面/多开洞）才降级 `tMeshOnly`（首次失败后改＝交付缺陷类修复；用户已指定模式后再改＝必须先问） |
| **总体网格尺寸**（★ 必须综合判断，不得一刀切） | 无通用值：按①模型总体尺度与单位制 ②**最小特征尺寸**（最薄板厚/最小截面边长）③分级尺寸 `beamSize`/`wallSize`/`plateSize` ④分析目的（位移可粗、应力需细）⑤预估单元规模与耗时（尺寸减半→单元 2~4 倍、实体可达 8 倍）⑥几何复杂度综合判断；起点参考：梁柱 0.3~0.6 m 截面 → `beamSize` 0.3~0.5；大体积实体 → 特征尺寸 1/8~1/20；孔口/支座局部加密且**相邻尺寸比 ≤ 2:1 逐级过渡**；**依据与预估规模写进规格核对表**，大模型先与用户确认（维度表见 `references/stru/mesh.md` §7） |
| 荷载与分析（混合路线） | 自重 + 一个主导工况；默认线性静力（模态则 `nModal=10`） |

> 用户表述含糊时，**先输出参数表请用户确认，再生成脚本**；不凭猜测先写一版。

### 第 2 步 — 生成

- **脚本生成方式**：**几何/混合路线一律 `save_script` 手写 Python**（`generate_script` 的 spec 通道不覆盖几何与网格）；**有限元路线**可用 `generate_script`（spec）或 `save_script`，复杂/非线性一律 `save_script`；
- 骨架与铁律见 `references/stru/script_standard.md`；构件 API 见 `references/stru/stru_model.md`；网格见 `references/stru/mesh.md`；
- ★ **网格块按默认策略显式写出**（`MeshParams(sizer=Size(...), meshPattern="sweepAndTMesh", hexMeshPattern="sweepOnly", toQuad="true")`，写在 `StruModel.toViewer()` **之前**）：体网格六面体主导、面网格四边形主导、六面体扫掠；`basicSize` 按 `references/stru/mesh.md` §7 维度表综合判断后填值，并在脚本注释里写明**取值依据与预估单元数**；
- 关键维度在脚本顶部用常量一次定义（`BAY=6.0`、`N_BAY=2`、`FLOOR_H=3.0`、`N_FLOOR=3`、`MESH_SIZE=0.5`），
  生成后立即自检数量关系：开间 N → 柱位 (N+1)²；层数 N → 节点层 N+1；柱 = 柱位数×层数；
- 保存前 `browse_generated_files()` 查重；多版本方案写入区分后缀（`_mesh0.25`/`_v2`）。

### 第 2.5 步 — 规格核对（SPEC，运行前必做）

生成脚本后、提交前，**必须向用户输出一份「建模规格核对表」**（模板见
`references/execution_contract.md` §2.2），逐项列出并核对：

| 类别 | 核对项 |
|---|---|
| 路线 | 结构（几何）/ 混合；建模模式（建筑结构 / 通用几何）；在哪个页面执行、哪个页面刷新视图 |
| 基础 | 单位制、坐标系、构件几何与数量（开间↔柱位、层数↔节点层已自检） |
| 属性 | 材料（`MatDB` 查库所得）、截面形式与尺寸、`SectionType` 与构件维度匹配、需生成单元的构件已挂 `sid` |
| 边界与荷载 | 点约束/线约束（`BaseLine`/`BaseLineGeom`）、弹性支座（须 FEM 阶段重建）、荷载工况与作用对象（几何阶段传构件号）、自重 |
| 网格 | `basicSize`/分尺寸/加密部位/`toQuad`/`meshPattern`、**预估单元规模与耗时**（规模大先与用户确认） |
| 求解 | 分析类型与必配参数、`Step`/`Analy` 装配、**`Job`+`JobManager` 任务指派**、模态/谱分析的 `LoadToMassSetting` 质量源 |
| 交付 | 结构路线 → 几何模型与网格产物（求解在界面提交）；混合路线 → 需要哪些结果量与对应 `.out` 文件 |

规则：

1. **关键规格缺失 → 停下来问用户，不得自行猜测或补默认值**；**路线永远属关键项**（用户未明说必问）；
   其余关键项：主要几何尺寸、材料牌号、边界条件、荷载量值与方向、分析类型、网格策略（用户已指定时）、质量源；
2. 只有非关键项允许取默认值，且必须标 `[默认]`/`[估算]` 并写进"未决/假设"行；
3. 用户确认（或未反对）后再执行第 3 步提交；用户指出条目号要改 → 改脚本 + 更新核对表，再提交；
4. 核对表随最终交付包一起再输出一次（取值列填脚本中的真实常量与实际网格规模），保证"说的"和"建的"一致。

### 第 3 步 — 提交（按路线收口）

```python
# A. 结构（几何）路线：只出几何模型 / 几何 + 网格
StruModel.toViewer()          # 1) 几何模型可视化（不可省；同时快照网格参数）
StruModel.submitAndMesh()     # 2) 自动划分网格（按需；成功不终止脚本，失败 sys.exit(-1)）

# B. 混合路线：几何 → 网格 → 有限元 → 计算（init_ctx 在 import 之后、clc() 之前）
StruModel.toViewer()          # 1) 几何模型可视化
StruModel.submitAndMesh()     # 2) 网格划分（仅 MIXED 模式生成 pypcae.fem.in）
FemModel.fromViewer()         # 3) 读入有限元模型（内部先 clc()，几何对象与 id 作废）
# ... 荷载 / 工况 / Step / Analy 写在这之后，编号重新取 ...
FemModel.toViewer()           # 4) 有限元模型可视化
FemModel.submitAndSolve()     # 5) 模型检查 + 提交计算
```

> **交付时必须说明界面行为**：几何模型页面与有限元模型页面都能执行混合脚本，但几何页面不能执行
> 纯有限元脚本、有限元页面不能执行纯几何脚本；视图只刷新与所在页面相关的部分（几何页面只响应
> `StruModel.toViewer()`、有限元页面只响应 `FemModel.toViewer()`），"跑完当前页面没变化"属正常现象。

### 第 4 步 — 诊断（症状 → 日志 → 修复）

**日志读取顺序**（禁止跳步，禁止只让用户贴日志）：

```text
1. pserver.log           PkpmCAE 安装目录 resources/ 下；空则取 pserver.YYYY-MM-DD.001.log 最近一份
                         —— 网格与求解各阶段的真实错误行在此（★ UTF-8 编码读取，2026-10-14 实测更正）
                         ★ 从后往前找第一个 @failure / **Error: / exit status 0xffffff9c，
                           以它所属的 [ xxx ] 前缀为准（sep-processor / sep-modelcheck / genfea）
                         ⛔ 不要以 run_script 的 msg 为准 —— msg 可能指向一个已 @complete 的阶段（#80）
2. 网格产物目录          <项目>/pcaestru-mesh/：StruDataSource.json、StruData.txt/TrStruData.txt、
                         UserMeshParameter.txt、fe_modelSource.json
                         日志标记：save:* → mesh:* → mesh-save:*（见 references/stru/mesh.md）
                         ⚠️ 该目录下的 *.inp 是网格阶段"空模板"（*binding 0 / *dofFixed 0），
                            核对绑定·约束·工况一律读 genfea-compute-*/ 下的同名文件（#103）
3. 模型检查/求解日志     read_check_log(项目 dir)：ModelCheckResult.json、genfea-compute*/log.out（GBK）
                         ⚠️ 核对时间戳/nElem，可能命中历史旧日志
                         ⚠️ genfea-compute-* 每次运行新建、失败目录不清理 → 须按 mtime + nNode/nElem
                            双条件锁定本次目录，否则会读到上一轮失败版本的产物（#81）
                         ⚠️ task-log/*.txt 是历次运行的累积文件 → 按"任务执行成功!/失败!"切段，
                            只看最后一段（#91）；模型检查日志可能是 0 字节空文件，空文件 ≠ 检查通过（#104）
4. 回读脚本              read_script(路径)，按日志中的构件/单元/节点号定位代码
```

> ★ **编码分工（2026-10-14 实测更正，#40/#56）**：`resources/pserver.log` = **UTF-8**；
> `genfea-compute*/log.out`、`Out*/*.out` = **GBK**；同目录 `.inp`、`task-log/*.txt` = **UTF-8**。
> 读错编码时中文关键词计数会**静默为 0** → 误判"算没算/报没报错"；**先确认中文能正常显示，再匹配关键词**。
> ★ `live_task()` 返回 **JSON 字符串**（不是 dict）：须 `json.loads()` 后再取 `result.uuid`/`result.dir`（#102）。

症状速查（完整版见 `references/stru/error_diagnosis.md`）：

| 症状 | 首选动作 |
|---|---|
| `禁止在几何模型中执行有限元脚本。` | 混合脚本漏了 `init_ctx(mode=ExecutionMode.MIXED)` |
| `FemModel.fromViewer()` ~~读不到模型~~ / 静默得到空模型 | `pypcae.fem.in` 未生成：非 MIXED 模式或 `submitAndMesh()` 未成功。★ **2026-10-22 更正：缺文件时 `fromViewer()` 不抛异常，只记 `**Error: 找不到文件` 后返回空模型**（#127） |
| 脚本跑到 `submitAndMesh()` 就结束 | 网格管线失败（`sys.exit(-1)`）——读 pserver.log 与 `pcaestru-mesh/`，不要拆脚本 |
| 改了网格尺寸没变化 | `MeshParams` 写在 `toViewer()` 之后（快照已固定）→ 前移 |
| 网格划分失败 | 构件未挂 `sid`、几何碎面/短线、尺寸过小；实体为主改 `meshPattern="tMeshOnly"` |
| 圆弧变成直线 | `Line` 漏传 `center`/`kp`（静默退化） |
| 墙/板网格畸形 | `Wall` 角点序、`Plate` 绕序错 |
| `zero pivot` / 刚度奇异（混合路线） | 约束不足或有限元阶段约束漏加（写在 `fromViewer()` 之后）。★ **实体模型最常见漏项是「绕 Z 转动」**：形心点 x=y=0、绕 Z 转动位移恒为 0，约束形心的 `Ux,Uy` 拦不住 → 须在底面 `y=0` 边补 **1 个非形心节点**的 `Uy`（#77）。定位用 **`neq` 差值核账法**：`nNode×3 − neq` = 约束+嵌入消除数；账目对上仍奇异 ⇒ 是刚体自由度，对不上 ⇒ 某类相互作用没生效（#79） |
| `**Error:judgeEmbedElemType出错: 不允许梁单元嵌入` | 钢筋用了 `Line` + 圆截面（网格后是**梁单元**）→ 改 `BeamColumn(iMark=ComponentType.TRUSS, sid=..., normal=...)`，网格后才是 Link 二力杆（★ P0，#76）。⚠️ 该错误只在求解器读入时才报，建模/网格/模型检查全通过 |
| `**Error:边界点夹角有错-2` 且 0 单元 | 用 `Surf(Cylinder)` 以「同标高、不同半径」两整圆拼**水平环面** → 改 `Surf(outer=[外整圆], inners=[[内整圆]], type=SurfType.Plane)`（#84） |
| 位移达 **米级量级**、约束圈节点数对不上 | `Fixed(type=BaseLineGeom)` **传多条线只展开一条**（静默缺陷，`run_script` 仍报成功）→ 每条线一个 `Fixed` 组，或改在 FEM 阶段按坐标重筛节点做点约束（#87） |
| 内压/外压算出的位移**方向反了** | `Wpload` 壳面**面号指向与直觉相反**：按"形心沿法向偏移落点在流体内部→side=1"赋值得到向内位移（错）；**翻转为"内部→side=2"** 才正确。校核：受压面平均径向位移符号应与压力指向一致（#88） |
| 湿面/受压面单元**漏选**（数量对不上） | 用**形心+容差**筛会因**曲壳弦效应**漏选（形心内偏 `r*(1-cos(pi/n))`；实测三次迭代 58→2266→2290）→ 改**逐节点判定**（单元全部节点是否落在湿面上，容差 1e-6）（#88） |
| 按坐标筛节点得到假阳性（"孔内有母材节点"） | **孤立节点**：圆弧/整圆构造的圆心点与 `kp` 方向点进了节点表但被 **0 个单元引用**（实测 74 个）→ 先解析 `12_Elem.inp` 统计引用次数、剔除 0 引用者再判断（#95） |
| 开孔实体六面体占比骤降 + `tmesh` 报"扭曲四边形" | 含孔/复杂实体被强行扫掠 → 用**实体分割**：含孔段留四面体、无孔段扫掠六面体，两段 `Binding(NodeToSurf)` 绑定（实测六面体 25.5%→**76.3%**、告警消失）。⛔ 不要靠调网格尺寸去消该告警（#93） |
| 网格/求解已完成但 `run_script` 返回 `success:false` | 脚本尾部 `import numpy`（内嵌 Python **无 numpy**）→ 删掉第三方库 import，后处理改在 Agent 本地做；⚠️ **此时产物已落盘**，不要误判为计算失败（#90） |
| 校验报「荷载工况 'XX' 无任何荷载定义」但该工况确有荷载 | `save_script` **假阳性**：两个 `LoadCase(...)` 相邻创建、`.add()` 写在之后的循环里 → 把每个 `LoadCase` 的创建与其 `.add()` **紧邻**（或按工况拆独立循环）即通过，**不改任何物理量**（#92） |
| 用了 `Connector` 后 `zero pivot` / `solveLinearEquaOne出错` | 多半不是连接器的问题：① **梁/杆系自由端缺 `Dof.Phx`** → 扭转刚体模态（扭转刚母子矩阵 `[[GJ/L,−GJ/L],…]` 本身奇异）；② 两端节点其余自由度没兜住。用 `neq` 核账法定位（账目吻合 ⇒ 是刚体自由度）。实测补 `Phx` 后 `neq` 48→47 一次通过（#115） |
| `**Error:readElemLoadInfo出错:*elemLoad:-1`（genfea） | **模型零单元**（只有节点 + 连接器/约束/荷载）→ 补至少 1 个单元/构件（#116）。前兆：modelcheck 报"模型未定义截面/材料"——**别误判成材料截面写错** |
| `TypeError: unexpected keyword argument 'iType'`（写在 `Section(...)`） | `Section` 用 **`type=`**、`iType=` 是 `MatDB.assemble` 的（两者相反）→ 改 `Section(name=..., type=SectionType.Line, sub=[...])`（#117）；属执行类错误，脚本在 Python 层即终止、走不到 modelcheck |
| 纯模态结果疑似"没指派分析" | ⛔ 不要用静力那条"看 `61_LoadStep.inp` 步名"判据（模态本来就没有荷载步，会误判）→ 改比对**模态结果文件的待求阶数 vs 脚本 `nModal`**（相等=自建分析；等于默认 3 阶=跑了空分析）（#101） |

## 2. 黄金法则

1. **禁止编造 API** —— 一律从 `references/` 复制或用 `scripts/manual_search.py` 查手册原文；不确定写进对应路线的 `known_issues.md` 并向用户说明。
2. **路线先定** —— **有限元 / 结构（几何）/ 混合 三选一**（判据见 `references/routes.md`），未明必问；"要自动网格 + 要计算结果"＝混合路线；常规杆系要结果＝有限元路线。
3. **时序不可颠倒** —— 混合路线五步；网格设置在 `toViewer()` 之前；荷载与分析在 `fromViewer()` 之后。
4. **单位制唯一** —— 材料库为 m 制（SI）：用户指定时换算一致，未指定默认 m 制并提示；网格尺寸同单位制。
5. **日志是地面真相** —— pserver.log / `pcaestru-mesh/` 产物 / ModelCheckResult.json / log.out 优先于任何猜测。
   ★ 编码别记混（2026-10-14 实测）：`resources/pserver.log` = **UTF-8**；`genfea-compute*/log.out`、`Out*/*.out` = **GBK**；同目录 `.inp`、`task-log/*.txt` = **UTF-8**。读错编码时中文关键词计数会**静默为 0**，先确认中文能正常显示再匹配关键词（ERRATA #40/#56）。
6. **⛔ 执行无报错即停止，禁止自行分析结果** —— 脚本顺利生成 + 执行无报错 + 网格与结果文件已生成 → 立即收口停止；
   只做"存在性"核对（`cells>0`、步名非 `step-1`、结果文件非空、位移/反力不全 0、模态无零频、Job 已指派），
   **不做** ΣR 定量平衡、理论对照、公式推导、量级评判、网格收敛性研究。原因：Agent 不完全熟悉软件
   （程序梁含剪切变形、曲面离散使网格体积小于理论值、节点应力为伪总体系平均、刚性耦合参考点反力为 0），
   盲推可能与软件定义不一致而误导用户；多轮自查还会烧掉巨量 token，且长对话可能无法保留。
   对照与验证**只在用户明确要求后**执行，且须声明公式可能与软件定义不一致（`references/execution_contract.md` §4b）。
7. **大模型先确认** —— 预计网格规模巨大或计算耗时较长时，先与用户确认再提交。
8. **用户指令优先** —— 用户明确指令与内部铁律冲突时以用户指令为准；工具校验报错属预期时照常交付并说明原因，不为过校验违背用户指令。
9. **规格先核对** —— 提交前必出「建模规格核对表」（含路线、构件数量、网格参数与预估规模、任务指派、执行页面）；关键规格缺失就停下来问（**路线永远必问**），不猜、不擅自补默认值；取默认值的项必须标 `[默认]`/`[估算]` 并列进"未决/假设"（`references/execution_contract.md` §2）。
10. **验收后才说完成** —— `success:true` 与"任务执行成功!"只代表脚本没抛异常；"完成"= 验收项全过（网格 `cells>0`、`61_LoadStep.inp` 步名非 `step-1`、ΣRz≈总荷载、结果文件存在·非空·含所需变量、warning 全部列出）；**求解正常结束 ≠ 结果物理正确**，禁止说"结果正常/安全/合格"（§3-§4）。
11. **不越界** —— 未经用户明确指令：不判断结果是否合理/安全，不自动改构件几何·材料·边界·荷载·接触·**网格策略**·求解设置，不自动做网格无关性/参数扫描/优化/重跑，不以"看起来不对"为理由改模型，不擅自拆脚本或切换路线；成功交 `SUCCESS_WAIT_USER`、失败交 `FAILED_NEED_USER`，然后停下来等用户（§5-§9）。
12. **⛔ 需要综合判断就问，不自己扛** —— 凡涉及"结果是否合理/可信/可接受、ΣR 要不要定量核对、网格够不够细、数值异常怎么处置、要不要改构件或网格、是否进入下一阶段"，一律**列成问题咨询用户**，不自作主张、不自行推导、不多轮自查。**CAE 桥接器 可以生成结果和辅助判断，但不能替代工程师对结果可信度和工程结论负责。**
